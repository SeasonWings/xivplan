# FFXIV Raid Planner 多人协作功能使用说明

本文档介绍了如何使用和部署FFXIV Raid Planner的多人实时共享战术板功能。

## 功能概述

- 实时多人协作编辑战术板
- 房间系统，支持多人加入同一个战术板
- 用户在线状态显示
- 实时聊天功能
- 通过URL分享房间
- 主机-访客模式，主机的更改会同步给所有访客

## 服务器部署

### 1. 安装依赖

进入backend目录并安装所需的依赖：

```bash
# 进入backend目录
cd backend

# 安装依赖
npm install
# 或者使用pnpm
pnpm install
```

### 2. 运行WebSocket服务器

```bash
# 在backend目录中运行
node server.js
```

默认情况下，服务器会在3000端口启动。你可以通过环境变量更改端口：

```bash
# 在backend目录中运行
PORT=8080 node server.js
```

### 3. 服务器配置（可选）

如果你需要在生产环境中运行，可以：

1. 使用PM2等进程管理工具保持服务器运行
2. 配置反向代理（如Nginx）以支持HTTPS
3. 对于公网访问，确保防火墙开放了相应端口

## 客户端使用

### 1. 构建前端

```bash
# 在项目根目录运行\pnpm install
pnpm run build
```

### 2. 使用协作功能

1. 在战术板界面点击顶部工具栏中的"协作模式"按钮
2. 右侧会显示协作面板
3. 你可以：
   - 创建新房间（自动成为主机）
   - 输入房间ID加入现有房间（作为访客）
   - 复制房间链接分享给他人
   - 更改自己的用户名
   - 与其他用户聊天

### 3. 协作注意事项

- 只有房间主机的更改会同步给所有用户
- 访客可以查看但不能直接修改战术板（除非被提升为主机）
- 刷新页面后会自动尝试重连到之前的房间
- 通过URL参数 `?room=房间ID` 可以直接加入特定房间

## 技术实现说明

### 后端（Node.js）

- 使用`ws`库实现WebSocket服务器
- 房间管理系统，支持多房间并发
- 用户会话管理
- 场景数据同步机制
- 自动清理长时间未活跃的空房间

### 前端

- WebSocket客户端服务，支持自动重连
- React上下文管理协作状态
- 实时场景同步
- 用户界面组件（协作面板、用户列表、聊天）
- URL参数处理，支持通过链接加入房间

## 故障排除

### 连接问题

- 确保WebSocket服务器正在运行
- 检查防火墙设置，确保端口开放
- 在浏览器控制台查看连接错误信息
- 确认客户端代码中的服务器URL配置正确

### 数据同步问题

- 确保只有一个主机在编辑战术板
- 刷新页面重新加入房间
- 检查浏览器控制台是否有JavaScript错误
