# 上线回滚方案

## 回滚触发条件

- 关键接口错误率上升
- WebSocket 连接失败率明显上升
- 影响核心业务流程的回归问题

## 回滚策略

1. 保留旧入口文件与旧路由文件（只作为回滚备份，不作为默认入口）
2. 回滚步骤
   - 将部署版本切回上一个稳定版本（包含旧 app.js 与旧路由挂载方式）
   - 恢复旧的依赖锁定文件（pnpm-lock.yaml）
   - 重启服务并验证 `/api/health` 与关键接口
3. 数据层兼容
   - 本次重构不涉及数据库 schema 变更，回滚不需要额外迁移

## 观测

- `/metrics` 指标
- server 日志与 ws 日志
